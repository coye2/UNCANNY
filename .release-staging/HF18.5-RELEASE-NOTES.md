# UNCANNY v0.20.0-alpha.1 — ELYSIUM Engine 4.5 — HF18.5

HF18.5 repairs the launcher/library failures reproduced on a tester machine after HF18.4.

## What was actually broken

The tester log showed two concrete failures:

- the official launcher PNG reached WPF in an image encoding that failed with **“The image format is unrecognized”**;
- cached/scanned library data still hit a missing-property path during content rendering, while earlier scans had successfully discovered games.

## Fixed

- **Scan PC / startup scan:** the packaged scanner resolves its PowerShell dependencies from the `runtime\` directory where they actually ship.
- **Library handoff:** cached, manually added, and scanned records are canonicalized through guarded property access before WPF binding. Legacy `Path`, `Exe`, missing optional fields, and malformed stale records cannot blank the whole list.
- **Path normalization:** remaining brittle `Resolve-Path(...).Path` reads were removed from the relevant discovery/normalization helpers.
- **Official logo:** the shipped asset comes from the official Library file `Monochrome Circular U Emblem(1).png`. It is cropped/resized from those exact source pixels into a 64×64 RGBA PNG; no vector redraw or generated substitute is used. The launcher also converts it through 32-bit ARGB before WPF display.
- **Diagnostics:** recovered cache/render/scan failures now include PowerShell stack and invocation-position evidence.

## Preserved

HF18.4 process-scoped startup recovery, installed-game path hardening, updater ordering, stale-Lucid migration, PCSX2, REVENANT, rollback, Universal API Bridge, Adaptive Realism, Motion Guard/Ghosting Guard, and the HF18 rendering stack remain intact.

## Release gate

HF18.5 is published only from the exact candidate that passes:

- full static/regression suite
- x86/x64 production + Engine 4.5 acceptance builds
- Windows HLSL compilation
- D3D11 WARP rendered-quality validation
- **packaged malformed-cache → WPF render test**
- **packaged official-logo load test**
- **packaged scanner execution from `runtime\`**
- normal packaged launcher startup
- AllSigned packaged launcher startup
- exact ZIP hash/extraction
- Microsoft Defender ZIP + extracted-tree scan

UNCANNY remains unsigned; SmartScreen/Unknown Publisher can still appear until trusted Authenticode signing is configured.
